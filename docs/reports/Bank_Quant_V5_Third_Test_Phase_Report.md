# Bank Quant V5 第三次测试阶段性汇报

日期：2026-07-15

## 一、阶段定位

第三次测试的目标不是继续追求单一策略收益最大化，而是验证 Bank Quant V5 是否已经具备“研究假设 -> 点时点数据 -> 统计验证 -> 本地模拟聚宽 -> 聚宽代码导出”的完整量化研发流程。

本轮测试围绕“银行高股息可持续性 V3”展开。核心问题是：银行股高股息是否只是价格下跌后的表面高收益，还是在 ROE、拨备覆盖、资本充足、估值合理等条件支持下，具备可解释、可验证、可复现的投资价值。

本轮所有结论都按实验分层管理：

| 层级 | 用途 | 是否可作为策略接受依据 |
| --- | --- | --- |
| research_pit_validation | 研究假设与因子验证 | 可以作为研究证据 |
| platform_replication | 本地模拟聚宽与平台对齐 | 不能作为研究证据 |
| engineering_smoke_test | 工程链路测试 | 不能作为研究证据 |
| paper_trading | 未来实盘/模拟跟踪 | 作为前瞻观察 |

## 二、本轮做了什么

### 1. 建立 JQData 点时点研究面板

新增 JQData PIT 面板采集流程，使用 DataJQ/JQData 基础接口重建银行板块研究面板。已验证可访问的数据包括：

- A 股证券基础信息；
- 股票真实价格与前复权价格；
- 512800 银行 ETF 基准价格；
- PB、ROE 等基础估值与财务指标；
- 现金分红数据。

生成面板规模：

| 项目 | 数值 |
| --- | ---: |
| 面板行数 | 1547 |
| 调仓日期数 | 57 |
| 银行股票数 | 42 |
| 采集警告 | 0 |

这个步骤解决了前两轮最大的问题：研究验证不能只依赖 V4 迁移数据，而需要一条 V5 自己可复现的数据路径。

### 2. 修复 notice_date 泄露审计

第一版 V3 测试发现正式验证存在 notice_date 缺失：

```text
missing_notice_date_rows = 1547
status = needs_review
```

第三次测试补入 `factor_visible_date`、`bank_quality_notice_date` 与更严格的泄露审计后，结果变为：

```text
missing_notice_date_rows = 0
future_notice_violations = 0
status = pass
```

这意味着当前研究面板已经可以判断每个调仓日能否看到对应信息，避免把未来财报数据提前用于历史回测。

### 3. 接入东方财富银行质量字段，但识别出样本不足

本轮尝试把东方财富银行专属质量指标接入本地面板，重点包括：

- 拨备覆盖率；
- 资本充足相关指标；
- 银行资产质量字段；
- 业绩公告时间。

接入结果：

| 数据类型 | 记录数 |
| --- | ---: |
| 银行质量记录 | 139 |
| 拨备记录 | 104 |
| 资本记录 | 136 |
| 公共样本调仓日 | 4 |

结论：东方财富字段方向正确，但当前公共样本太少，不能作为正式因子有效性的充分证据。它更适合作为后续数据采集方向，而不是现在直接接受为策略核心。

### 4. 迁移 V4 银行质量长样本并做临时验证

为了判断银行专属质量因子是否值得继续投入，本轮迁移了 V4 最终版中保存的银行质量数据：

| 项目 | 数值 |
| --- | ---: |
| 质量快照 | 310 |
| 银行股票数 | 41 |
| 来源年份 | 2013-2023 |
| PIT 质量面板行数 | 1365 |
| 公共样本调仓日 | 47 |

基于长样本的主要证据：

| 因子 | IC | RankIC | 正 IC 占比 |
| --- | ---: | ---: | ---: |
| dividend_yield | 0.1731 | 0.1735 | 77.55% |
| provision_coverage | 正向但较弱 | 正向但较弱 | 高于随机 |
| core_tier1_capital_ratio | 单独解释力弱 | 单独解释力弱 | 不稳定 |

组合层面，高股息叠加质量支持字段略好于单纯高股息，但该结论依赖 V4 遗留数据的来源日期假设，因此只能作为研究线索，不能直接作为正式策略接受依据。

### 5. 建立本地模拟聚宽测试流程

本轮继续完善本地模拟聚宽，用真实 open/close、现金、分红、调仓、100 手限制、银行 ETF 基准等规则，复刻聚宽近 5 年测试口径。

## 三、达成的目的

### 1. 从“策略回测”升级为“研究流程验证”

V5 第三次测试的最大成果不是某一个收益数字，而是建立了一个可以反复使用的研究闭环：

```text
研究假设
-> 点时点数据采集
-> 泄露审计
-> 因子统计验证
-> 本地平台复刻
-> 聚宽代码导出
-> 逐日归因
-> 未来 paper trading
```

这说明 V5 已经不再只是一个策略脚本，而开始具备 AI 驱动量化研究平台的雏形。

### 2. 明确区分“研究成立”和“工程复刻成功”

本轮把实验结果分成多个层级，避免把不同性质的结果混在一起：

- 本地模拟聚宽跑得好，只能说明工程流程可以运行；
- 聚宽近 5 年表现好，只能说明平台口径下结果存在；
- 因子在 rolling / ablation / baseline / robustness 中稳定，才可能说明研究假设成立；
- 未来 paper trading 记录，才是对真实未来表现的前瞻观察。

这对后续减少过拟合非常关键。

### 3. 发现高股息因子确实值得继续研究

长样本初步显示，银行股股息率具有较稳定的正向预测关系，RankIC 与正 IC 占比都优于随机水平。它不是最终结论，但已经足以支持继续投入第三阶段研究。

### 4. 发现银行专属质量因子的数据瓶颈

东方财富字段方向正确，但当前公共样本不足。V4 质量数据能提供长样本线索，但来源日期还要进一步审计。因此下一步重点不是马上优化策略，而是补齐银行专属质量数据的可靠来源与可见日期。

## 四、相比 V4 的提升

| 维度 | V4 | V5 第三次测试后的状态 |
| --- | --- | --- |
| 项目定位 | 更接近单策略开发 | 量化研究框架 |
| 数据处理 | 依赖已有数据与脚本经验 | 建立 JQData PIT 面板 |
| 泄露控制 | 主要靠人工经验 | notice_date 审计纳入流程 |
| 实验管理 | 结果容易混用 | 明确实验分层 |
| 因子验证 | 偏回测结果导向 | 增加 IC、RankIC、公共样本、ablation 思路 |
| 平台对齐 | 主要去聚宽反复试 | 建立本地模拟聚宽 runner |
| Agent 分工 | 经验驱动 | PM / Research / Quant / Engineering 职责拆分 |
| 复现能力 | 依赖个人记忆和流程 | 形成文档、脚本、runner、导出代码 |

总结来说，V4 的优势是积累了可用经验和策略雏形；V5 的提升是把这些经验变成可复用、可审计、可迭代的研究系统。

## 五、当前仍存在的问题

### 1. 本地模拟聚宽还没有完成逐日归因闭环

当前本地模拟已经能输出收益、持仓、交易、现金和分红日志，但还需要用户从聚宽导出每日收益 CSV 后做逐日归因。只有完成逐日对账，才能判断本地模拟是否真正贴近聚宽。

需要继续比较：

- 每日净值差异；
- 调仓日股票名单差异；
- 买卖数量差异；
- 成交价格差异；
- 分红到账日期与税费差异；
- 基准收益差异。

### 2. V4 遗留质量数据仍需来源日期审计

V4 长样本质量数据给出了积极线索，但正式使用前必须确认：

- 每个字段来自哪个公告；
- 何时可见；
- 是否存在后来修正；
- 是否在调仓日之前已经披露。

否则它只能作为探索性研究线索。

### 3. 东方财富银行专属字段需要扩展采集

当前东方财富质量字段样本太少。下一步需要研究员继续扩展：

- 更多年份；
- 更多财报期；
- 更完整的公告日期；
- 字段定义与财报来源；
- 与 JQData / 聚宽数据的交叉验证。

### 4. V3 还不能被正式接受为最终策略

当前 V3 可以进入下一轮测试，但不能直接定义为正式策略。原因是：

- 正式 rolling 验证仍需补全；
- baseline / ablation / robustness 还需系统跑完；
- 高股息与质量因子交互关系仍需更多样本；
- 本地与聚宽逐日归因尚未完成；
- 未来 paper trading 尚未积累。

## 六、下一步改进建议

### 1. 先完成本地 vs 聚宽逐日归因

这是最优先事项。目标不是提高收益，而是确认工程平台可信：

```text
本地每日净值
vs
聚宽每日净值
```

如果误差能被解释并稳定收敛，本地模拟聚宽 runner 才能作为后续主要测试工具，减少反复消耗聚宽积分和人工时间。

### 2. 补正式因子验证 runner

Quant Validation Agent 下一步应补齐：

- rolling validation；
- ablation；
- baseline；
- robustness；
- factor turnover；
- correlation；
- overfitting check。

这些结果决定 V3 是“研究假设成立”，还是只是“工程复刻成功”。

### 3. 重建银行质量数据的正式 PIT 来源

Research Agent 和 Data Collection Skill 需要继续补：

- 银行拨备覆盖率；
- 不良贷款率；
- 核心一级资本充足率；
- 净息差；
- ROE；
- 分红率；
- 公告日期；
- 数据来源引用。

每个字段必须记录 `source`、`report_date`、`notice_date`、`collected_at`。

### 4. 开始 paper trading 记录

从当前候选策略开始记录未来模拟信号，不用它做参数优化，只观察：

- 信号是否稳定；
- 调仓是否可执行；
- 持仓是否符合金融解释；
- 未来收益是否和历史统计方向一致。

## 七、阶段结论

第三次测试已经证明：Bank Quant V5 的价值不在于一次性找到“最优策略”，而在于建立了一个更接近真实量化团队的研究系统。

本轮最重要的进展是：

- 建立了 JQData PIT 研究面板；
- 修复了 notice_date 泄露审计；
- 区分了研究验证与平台复刻；
- 发现高股息银行策略值得继续研究；
- 发现银行质量数据是下一阶段核心瓶颈；
- 建立了本地模拟聚宽与聚宽代码导出的工程链路。

因此，V3 可以继续推进为候选研究方向，但还不能作为正式可接受策略。下一阶段应优先完成本地 vs 聚宽逐日归因、正式 rolling/ablation/baseline/robustness 验证，以及银行专属质量数据的 PIT 化。
