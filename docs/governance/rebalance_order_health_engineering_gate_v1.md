# Rebalance Order Health Engineering Gate V1

Date: 2026-07-21

Owner: Engineering Agent + Project Manager Agent

## Purpose

Local JoinQuant-like simulations must prove that rebalance signals actually lead to executable local orders and post-rebalance holdings before any platform-replication gate.

This gate was added after repeated cases where a strategy could have a valid signal file but still fail to place orders in the first rebalance windows because of cash, lot-size, tradability, data coverage, or implementation issues.

## Required Output

Every local JoinQuant-like daily simulation must output:

```text
rebalance_order_health.csv
```

and include this object in `summary.json`:

```text
rebalance_order_health
```

## Blocking Conditions

PM Gate must block platform replication when any of these occur:

- missing `rebalance_order_health`;
- rebalance signal exists but no order was executed;
- rebalance signal exists but no selected holding exists after rebalance;
- buy or sell order is blocked / unfilled by cash, lot size, high limit, low limit, suspension, or missing price;
- rebalance date is missing from daily simulation rows;
- leading rebalance dates have no order and no selected holding.

If a no-order date is intentional, Engineering must explain it in an attribution packet before PM can continue.

## PM Decision

`rebalance_order_health` is now a required Engineering gate for local JoinQuant-like tests.

Allowed:

- continue platform-export intake preparation;
- rerun local simulations for health inspection;
- use the health CSV for daily attribution and execution diagnostics.

Blocked:

- platform replication when health output is missing;
- platform replication when any rebalance date has unexplained no-order / no-holding / blocked-order status;
- accepting a strategy based on local execution health alone.
